# 日常使用手册

## 先记住三个规则

1. 普通对话、稳定偏好、通用知识和跨项目经验写入全局记忆。
2. 某个项目的任务状态、决定、代码事实和检查点写入该项目自己的记忆。
3. 系统不会永久保存每一句话；需要明确记住的内容要主动保存，长任务则用检查点交接。

## 五个常用入口

这些名称是 Codex 中的 Basic Memory Skills，不是 PowerShell 命令。

| 目的 | 使用方式 | 结果 |
| --- | --- | --- |
| 保存一个小事实 | `$bm-remember` | 一条轻量记忆 |
| 记录重要决定 | `$bm-decide` | 含理由、替代方案和后果的决定笔记 |
| 保存任务交接点 | `$bm-checkpoint` | 不可覆盖的会话检查点和恢复标识 |
| 恢复任务 | `$bm-orient "<标识或主题>"` | 读取相关笔记并核对当前现场 |
| 检查系统状态 | `$bm-status` | 配置、Project、Hook 和最近检查点摘要 |

## 什么时候会保存

记忆主要在以下时机产生：

- 你明确说“记住这个”时；
- 你要求记录一个决定时；
- 你主动创建检查点时；
- 长对话发生上下文压缩，恢复后的 Codex 按 Hook 提示创建检查点时；
- 你明确要求整理某段对话为知识或经验时。

普通闲聊不会自动逐句写入 Markdown。Hook 的生命周期事件只保存在本地运行轨迹中，不等于已经形成可回忆的知识笔记。

## 全局记忆

适合保存：

- 你长期稳定的工作偏好；
- 与任何单一项目无关的知识点；
- 多个项目都适用的方法和经验；
- 没有绑定项目的普通 AI 对话总结；
- 非项目性质的长期决定。

示例：

> 使用 `$bm-remember` 记住：我希望技术文档先给结论，再给验证步骤。

> 把刚才关于需求拆解的方法整理成一条通用经验，保存到全局 `experience/`。

不要把未经整理的某项目细节直接放进全局，否则以后所有项目都可能召回它。

## 项目记忆

适合保存：

- 当前任务做到哪里；
- 已验证的仓库结构和运行方式；
- 架构或工程决定；
- Bug 根因与验证结果；
- 未完成事项、阻塞和下一步；
- 与分支、SHA、PR 相关的检查点。

示例：

> 使用 `$bm-decide` 记录：本项目选择队列方案 A；原因是……；没有选择方案 B，因为……

> 使用 `$bm-checkpoint` 保存当前实现进度，列出改动文件、实际运行的测试和唯一下一步。

项目记忆默认只进入当前项目 Project。即使另一个项目中出现相同术语，也不应跨项目自动检索。

## 一个项目经验如何变成全局经验

不要直接移动原始项目笔记。推荐流程是：

1. 在项目内完成验证，保留原始证据。
2. 提炼真正可复用的结论，删除项目名、客户数据、内部路径等细节。
3. 明确说明适用条件和不适用条件。
4. 让用户确认是否提升到全局。
5. 在全局 `experience/` 新建总结，并链接回原项目笔记（如果安全且需要）。

这样既保留出处，也不会把项目噪声扩散到所有任务。

## 长对话压缩，但尚未绑定项目

这是正常情况。处理方式是：

- 使用全局 `general` profile；
- 把检查点写到全局 `conversations/`；
- 在检查点中注明“当前未绑定项目”；
- 只记录目标、最新意图、关键结论、验证、阻塞和下一步，不保存完整逐字稿；
- 日后确认属于某项目时，在项目 Project 新建决定或检查点并建立关系，不静默改写旧记录。

因此，未绑定状态不会导致记忆丢失，也不会被强行塞进一个错误项目。

## 如何恢复

检查点成功后会返回精确标识。以后可在新任务中使用：

```text
$bm-orient "<CHECKPOINT_IDENTIFIER>"
```

如果没有标识，也可以使用主题：

```text
$bm-orient "上次的部署验收"
```

精确标识更可靠；主题搜索适合探索。恢复时 Codex 应重新检查当前文件、Git 分支和测试状态，因为记忆可能已经落后于现场。

## 如何回顾知识

你可以直接说：

- “搜索全局记忆中与需求分析有关的知识，按主题归纳。”
- “只查看当前项目最近 30 天的决定。”
- “比较这个项目的两个检查点，告诉我状态发生了什么变化。”
- “把全局 experience 中适用于本任务的内容列出来，不要读取其他项目。”

关键是明确作用域：全局、当前项目或一个精确 Project。不要默认搜索所有 Project。

## 绝对不要保存

- 密码、API Key、令牌、私钥、恢复码；
- 客户隐私、身份证件、未脱敏业务数据；
- 完整聊天逐字稿；
- 大段可从 Git、Issue 或官方文档重新获得的原文；
- 未验证却被写成事实的猜测；
- 不清楚应该归属哪个 Project 的敏感项目内容。

对于权威信息，记忆应保存“结论 + 为什么重要 + 原始文件或链接”，而不是复制整份材料。

## 每周整理建议

只需做三件事：

1. 清理全局 `inbox/`：删除过期提醒，把稳定内容归入 `profile/`、`knowledge/` 或 `experience/`。
2. 查看各项目的开放决定和最近检查点，关闭已经完成的事项。
3. 选择少量真正跨项目复用的经验，经确认后提升到全局。

## 快速排错

- 保存位置不对：运行 `$bm-status`，检查 `primaryProject` 和最近项目级配置。
- 新任务不加载记忆：确认插件已安装、Hook 已审阅，并在配置变化后新建任务。
- 回忆太杂：缩小到精确 Project、note type、时间范围或 checkpoint 标识。
- 检查点写不了：`coding` profile 需要有效 Git HEAD 和稳定仓库标识；否则暂用 `general`。
- 担心泄漏：停止写入和 Git 操作，先检查目标 Project、候选文件和 `SECURITY.md`。
